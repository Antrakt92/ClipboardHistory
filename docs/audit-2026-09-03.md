# ClipboardHistory audit — 2026-09-03

Baseline: `92a8e315c5ed23b893f7fbba12fa9a4082875651`. Scope: startup, background overhead, clipboard privacy, paste races, and database recovery. Existing local history, clipboard contents, logs, autostart configuration, and running application instances were not inspected or modified.

## Confirmed findings and corrections

| Finding | Correction | Evidence |
| --- | --- | --- |
| A worker called Tk before `mainloop` while startup waited for listener readiness, causing an approximately one-second timeout. | Status remains in the thread-safe store during startup and is rendered from the main thread. Shutdown suppresses new status scheduling. | Regression plus real Tcl worker timing. |
| Startup imported CustomTkinter and constructed a popup that could remain unused. | Start with a hidden standard Tk root; import and create the themed popup on its first use, then reuse it. | Startup and first-use regressions; hidden real Tk/CTk smoke. |
| Recording pause still read the clipboard and converted screenshots before discarding them. | Check recording state before reads, before conversion, and before final delivery; retain the storage-side check. | Synthetic paused/read-transition tests. |
| Windows producer-supplied privacy opt-out markers were ignored. | Skip content with `ExcludeClipboardContentFromMonitorProcessing`, or a zero/malformed `CanIncludeInClipboardHistory` value. An explicit one permits capture; cloud-only opt-out does not disable local history. | Synthetic flag fixtures and Microsoft's documented format contract. |
| A pending retry survived the ignore-next paste event; already-running retries could publish stale captures. | Cancel and invalidate retries when pasting or handling new updates. Generation checks prevent stale timers from replacing current retries or publishing converted images. | Reproduced failures before the fix; timer and conversion-race regressions pass after it. |
| Paste sent keys even when activation failed, the target disappeared, or focus moved during the delay. | Require a valid, successfully activated foreground target immediately before key injection. | Invalid target, activation failure, and focus-switch regressions. |
| Clipboard changes during the paste delay could inject a different item. | Close the write, reopen read-only, verify the selected text/DIB payload, capture its sequence, and check the sequence before sending keys. Abort on unavailable or changed data. | Changed/unchanged sequence tests; simulated format synthesis on close; text/image readback and mismatch/busy/oversize regressions. |
| Any SQLite database error triggered quarantine, including locks and I/O errors. | Quarantine only an integrity-check failure or recognized corruption/not-a-database errors. Propagate operational failures while preserving the original database. | Synthetic operational-failure preservation tests and existing corrupt-database recovery test. |

The original test asserting successful paste after failed activation was corrected: accepting that result could send private text to a different application. No database schema, dependency, or autostart registry policy changed. Readback adds one payload read per paste, with a size check before reading; it adds no background work. Image writes release the temporary BMP buffer before verification. A failed readback retains write suppression because the clipboard write already occurred.

## Startup measurement

Five alternating fresh subprocesses for each revision, Python 3.13.15, Windows. Both versions used current installed dependencies and the same current component modules. Only the entry-point startup scaffolding differed. Database, migration, filesystem setup, application logging, icon creation, clipboard listener, hotkey, and tray services were mocked. Tk widgets were real and remained hidden. A separate Tcl interpreter exercised a worker status callback before `mainloop`.

| Metric, median | Baseline | Updated |
| --- | ---: | ---: |
| Entry-point imports | 108.314 ms | 50.187 ms |
| Hidden application construction | 71.363 ms | 35.393 ms |
| Worker status callback before mainloop | 1064.504 ms | 0.566 ms |
| Initially scheduled Tk callbacks, count | 8 | 0 |

The first popup opening pays the deferred UI initialization cost. These isolated measurements do not establish total Windows sign-in time, production CPU/RAM reduction, or startup latency with a large existing database. The callback count is a startup snapshot, not a steady-state wakeup rate.

Reproduce with:

```powershell
python tests/benchmark_startup.py 92a8e315c5ed23b893f7fbba12fa9a4082875651 --runs 5
```

The helper prints every sample and medians. It does not start the real listener, hotkey, tray, database, or autostart manager.

## Remaining manual Windows checks

Use synthetic, non-sensitive text and screenshots:

1. Launch normally and via the existing Windows sign-in configuration; verify a single tray icon, clipboard recording, and the first `Ctrl+Shift+V` opening.
2. Paste text and an image into a test editor. Confirm selecting history does not create a duplicate entry, including after temporary clipboard contention.
3. Switch focus or copy different synthetic text during the paste delay. Confirm automatic paste aborts; verify ordinary text/image pasting works when Windows synthesizes additional formats as the write is closed.
4. Pause recording, copy text and a screenshot, resume, then copy a fresh item. Confirm only the fresh item is recorded.
5. Exercise clipboard-history exclusion and explicit-allow formats with a disposable test producer. Confirm ordinary applications still record normally.
6. Check first popup opening, repeated opening, search, image preview, pin/delete, multi-monitor placement, and exit while a clipboard retry is pending.

Full foreground/tray/clipboard/autostart behavior was not exercised during the automated audit. SQLite integrity scans and synchronous compaction remain potential costs for large histories; see `audit.md`. File copies still paste as text paths, and text beyond the 50,000-character storage cap cannot be searched or pasted.
