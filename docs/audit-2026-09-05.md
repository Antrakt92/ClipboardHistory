# ClipboardHistory audit — 2026-09-05

The changes protect history while editing search, improve Unicode matching, and prevent held shortcut keys from changing an automatic paste. Work remains local and uncommitted; the user's clipboard, history database, running app, and autostart settings were not accessed or changed.

## Confirmed fixes

- **Search-field Delete:** the Entry class edited the query, then the popup's binding could also delete the selected history row. The popup now preserves the row when the event originates in a text field.
- **Stale search actions:** during the 150 ms debounce, Enter, pin, delete, or a row click could act on a selection from the previous query. Actions now compare the actual query with the displayed results, refresh stale results, and cancel the outdated action. Arrow navigation refreshes before selecting.
- **Unicode search:** SQLite's previous `LIKE` matching missed Cyrillic and other non-ASCII case variants. Literal Unicode casefold matching handles examples such as `ПРИВЕТ`/`Привет`, `STRASSE`/`Straße`, and `café`/`CAFÉ`; `%`, `_`, and backslashes retain literal meaning.
- **One page/count snapshot:** the popup now gets matching total and page metadata from one SQLite statement. A windowed CTE evaluates the text predicate once and retains only IDs, ordering fields, and counts. The result still includes total when a page is empty or its offset is beyond the results. Existing individual history/count APIs remain available.
- **Held modifiers:** paste waits up to 0.8 seconds for Ctrl, Shift, Alt, and either Windows key to be released; timeout cancels input. Clipboard sequence and foreground window are checked after the wait. The app does not synthesize releases for the user's held keys. Microsoft documents that [SendInput preserves existing keyboard state](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput); the guard uses the current-down bit from [GetAsyncKeyState](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getasynckeystate).
- **Clearer states:** an unsuccessful search says `No matches / Try a different search`; empty history retains its copy-to-start message. Truncated text explicitly says `First 50,000 of … chars`. Search and paste intentionally cover the stored prefix.

## Search measurements

Baseline: `56abaa2851181f9b8dcb7e46b1e43b0bc982a62a`, loaded from `git show HEAD:app/database.py` into an isolated Python namespace without changing working files. Each scenario used one temporary database shared by separate baseline/current connections. The dataset contained 500 unique rows built from `Синтетический ТЕКСТ ` repeated 5 or 2,500 times, followed by the row number. The no-match query was `НЕСОВПАДЕНИЕ`. One warm-up and seven measured samples were run, rotating implementation order. Numbers measure database calls only, without widget rendering or the search debounce.

| Synthetic text size | HEAD: separate page/count, ASCII-only case matching | Unicode: separate page/count | Final popup: combined Unicode page/count |
|---|---:|---:|---:|
| 500 × about 95 characters | 0.79 ms | 2.23 ms | 1.45 ms |
| 500 × about 47,500 characters | 165.86 ms | 496.25 ms | 265.52 ms |

The combined query removes the duplicate expensive scan, reducing the extreme Unicode lookup by about 46%. Correct Unicode matching still costs about 100 ms more than the old ASCII-only lookup on this extreme dataset. This is not a claim that all searches became faster; the remaining synchronous latency is tracked as CH-AUDIT-022. No cache or additional persistent copy of clipboard text was introduced.

## Remaining checks and constraints

- In the real popup, select a row with arrows, edit the query with Delete, and confirm the row remains. Quickly change query then press Enter, pin, or click an old row; the stale action should cancel and show current results.
- Paste synthetic text while releasing or retaining Ctrl/Shift/Alt/Win; verify normal paste or bounded cancellation. Switch window or copy different synthetic content during the wait and verify cancellation. Repeat with an image, paused recording, and an elevated target.
- Check the longer truncation label at display scaling and narrow work areas, and verify `No matches` is distinct from empty history.
- There remains a small check-to-input race if a modifier is pressed again after the last state sample. The Win32 checks and SendInput are separate operations; the change does not promise atomicity.
- Paste cancellation still reports only through the log (CH-AUDIT-023). A non-focus-stealing notification should distinguish failed copying from copying succeeded but automatic paste cancelled, without exposing content.
- **Review candidate, not a validated live bug:** if SendInput reports only 1–3 of its four events, the existing failure path logs the count without explicitly recovering a possibly missing Ctrl-up. No live partial-input reproduction or safe recovery policy was established in this audit.
- File clipboard still pastes text paths, large database compaction can block, and app-aware privacy/retention controls remain in `audit.md`. No manual Windows paste/tray smoke or running-app restart was performed.
